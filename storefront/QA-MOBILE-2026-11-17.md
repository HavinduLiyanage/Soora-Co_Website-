# Mobile layout verification — 17 November 2026

## Method
The browser viewport override did not reliably resize tabs. A temporary same-origin iframe harness therefore set actual document viewports to 320×720, 390×844, 768×844, 390×480 and 844×390. `window.innerWidth`/`innerHeight` were verified inside each frame; fitting the preview on screen did not change those viewport sizes. The harness was removed before committing. Testing used the local production build and imported inventory/admin preview; live data was not modified.

## Fixed
- Narrow inventory cards squeezed prices and clipped visibility because the quick-stock group required 170px. Price and visibility now share a row; availability gets its own full-width row.
- Edit/Delete actions now have a separate footer with readable Edit text and larger touch targets, avoiding overlap with product names and badges.
- Sale-editor date fields caused a small horizontal overflow at 320px. Grid columns and date controls can now shrink, while reducing nested spacing gives the date text more room.
- Image controls wrap on narrow screens. The editor action footer respects the bottom safe area.
- Mobile enquiry and admin search text use 16px; the mobile sign-out target is 44px.

## Passed
- [x] Customer home, collection, deals, brands, search, wholesale, contact, FAQ, policies, about and a product detail: no page-level horizontal overflow at 320, 390 and 768px.
- [x] Admin overview and login layouts at 390 and 768px.
- [x] Admin inventory, watch/sale editor, banner editor, settings and discard confirmation at phone widths; additional checks at 390×480 and 844×390.
- [x] Small-phone inventory row width equals its scroll width. Watch editor body width equals its scroll width after opening sale fields.
- [x] Tablet/landscape inventory retains its intentional internal horizontal table scroll; the page itself does not overflow. Editors and settings fit within the viewport.
- [x] Mobile menu open/Escape close, search dialog, filter drawer and applying a brand filter.
- [x] Product enquiry dialog, image enlargement, wholesale message preparation and readable form controls.
- [x] Admin navigation, edit, sale toggle/date input, banner editor, close/discard/confirm and settings navigation.
- [x] Production build and TypeScript compile; 21 automated domain/schema/database tests.
- [x] Rechecked corrected inventory and sale editor against the production build at 320px.

## Limits
These are browser-rendered responsive tests, not physical iPhone/Safari or Android hardware tests. Native keyboard behavior, physical safe-area insets, and OS WhatsApp handoff still require a device check. No WhatsApp message was sent. Disabled preview save/upload controls were not used to retest persistence; those paths were covered by the earlier authenticated browser/backend audit.
